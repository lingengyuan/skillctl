# 性能优化与消融

v0.0.4 在既有来源去重、并发和锁修复之外保留两项改动：安装历史读取复用缓冲区，同一来源的 Skill 目录在恢复会话内只扫描一次。目录、名称、重复候选和内容仍逐项验证。工具名预筛在实验中变慢，已撤掉。

上一轮的来源去重、最多 4 路并发和内核锁也纳入消融。目录拆分用于维护代码，不计作性能收益。

## 受控实验

2026-09-08，Apple M5、macOS arm64、Go 1.27.0、`GOMAXPROCS=4`。每个变体从同一份源码独立编译，只在临时副本中关闭指定机制。10 个变体各跑 7 轮，每轮随机顺序、每项执行 3 次。表中耗时是 7 个样本的中位数；每个样本是该轮 3 次操作的平均耗时，不能当作 21 个独立样本。

| 机制与场景 | 关闭该机制 | 最终实现 | 观察结果 |
|---|---:|---:|---|
| 来源目录复用：验证 20 个 Skill，来源含 200 个 Skill | 114.189 ms | 16.221 ms | 约 7.0 倍；两侧都成功验证 20 个 |
| 来源请求去重：32 个 Skill、8 个来源，每次固定 20 ms 失败 | 168.498 ms | 42.195 ms | 来源调用从 32 次降到 8 次 |
| 4 路并发：同一失败场景，保留去重 | 168.705 ms | 42.195 ms | 调用仍为 8 次，约 4.0 倍 |
| 去重与并发同时关闭：同一失败场景 | 673.702 ms | 42.195 ms | 两项联合约 16.0 倍，不能将各自降幅相加 |
| 读取缓冲区复用：约 17 MB 合成历史 | 14.425 ms | 12.904 ms | 累计分配从 21.57 MB 降到 1.64 MB |
| 退出进程遗留的缓存锁，50 ms 等待预算 | 21/21 次超时 | 21/21 次成功；0.107 ms | 旧策略没有完成，不能据此计算加速倍率 |

来源适配器使用固定本地结果；失败场景中的 20 ms 是模拟延迟，没有外网请求。目录和历史文件为热缓存。每轮均校验候选身份、验证数量，以及失败后不登记来源。这些是对应阶段的性能，不是整条 `check/update` 的加速倍率。

局部小差异需谨慎解释：缓冲区复用的每轮配对耗时比为 1.012–1.202，中位数 1.068，主要收益是减少分配；目录复用的配对比为 3.612–7.124，中位数 7.036。完整分布、分配量、调用次数及原始 benchmark 行见 [结果报告](../benchmarks/results/2026-09-08/report.md)、[JSON](../benchmarks/results/2026-09-08/results.json) 和 [CSV](../benchmarks/results/2026-09-08/samples.csv)。

## 真实历史数据

使用 157 个历史文件，共 945,455,724 字节，约 902 MiB；排除最近 5 分钟变化的 4 个文件。7 轮随机顺序测量后重新核对文件大小、修改时间和 inode，确认数据未变。各变体提取出的候选数量和内容摘要完全一致。报告仅保存数量、摘要和耗时，不包含历史正文或来源地址。

| 读取方式 | 耗时中位数 | 每次累计内存分配 |
|---|---:|---:|
| 原逐行分配 | 0.911 秒 | 1.608 GB |
| 缓冲区复用，最终实现 | 0.860 秒 | 0.621 GB |
| 缓冲区复用加工具名预筛，已放弃 | 0.939 秒 | 0.620 GB |

缓冲区复用在这组数据中减少约 61.4% 的累计分配，耗时减少约 5.6%。累计分配量不等于常驻内存或内存峰值。详见 [逐轮数据](../benchmarks/results/2026-09-08/local-history.json)。

工具名预筛增加了整行搜索，在合成历史中使耗时从 12.904 ms 增到 18.640 ms，在真实历史中也从 0.860 秒增到 0.939 秒。因此最终代码没有该预筛，实验脚本仅在临时变体中保留它。首轮筛选数据见 [初筛记录](../benchmarks/results/2026-09-08/screening/report.md)。

## 复现

```sh
python3 scripts/ablation.py --rounds 7 --iterations 3 --output benchmarks/results/local
python3 scripts/ablation_history.py --root ~/.codex/sessions --root ~/.claude/projects --rounds 7 --output benchmarks/results/local/history.json
```

仅需 Python 标准库、项目要求的 Go 和现有模块依赖。实验不调用远端来源，也不更新用户 Skill。完整矩阵使用生成的数据；第二条命令读取指定的历史目录，排除活动文件，并在结束时校验数据是否变化。Unix 使用临时链接，Windows 使用临时副本；文件发生变化会拒绝输出有效结果。

源码消融采用精确匹配的临时补丁；实现变化使补丁无法唯一匹配时会报错，不会静默测错变体。结果附带源码 SHA-256。`all_off` 是受控算法基线，并非完整的 v0.0.3 二进制。

## 验证边界

回归测试覆盖超长 JSONL、缺少末尾换行、Unicode 转义、重复名称、忽略目录和本地内容修改。目录索引只复用来源定位，不跳过每个 Skill 的内容校验，也不新增跨命令的来源缓存策略。

真实全量检查仍可能等待 Git 克隆或远端响应；这些等待不会因本轮的解析与扫描优化而消失。来源失败会保留为诊断，不能通过减少检查范围或跳过验证来制造更好的耗时结果。

最终程序的本机预览记录如下，均未修改已安装 Skill：

| 实机命令 | 耗时 | 结果 |
|---|---:|---|
| 全量 `check --dry-run --timeout 10s` | 25.879 秒 | 122 个条目；历史来源恢复超时、7 个来源检查错误，以及 2 个已有安装校验错误 |
| `update lark-doc --dry-run --timeout 10s` | 1.254 秒 | 发现可更新内容；仍有 2 个已有安装校验错误 |
| 随后 `check --dry-run --no-history --timeout 10s` | 4.196 秒 | 7 个来源检查错误未复现；仍有 2 个已有安装校验错误 |

这些实机请求没有固定外部服务和缓存状态；跳过历史恢复也改变了工作量，不能据此计算总命令的加速比。三个预览的退出码均为 1，不代表全量检查或实际更新成功。摘要见 [实机预览记录](../benchmarks/results/2026-09-08/live-preview.json)。

本地单元测试、Git 集成测试、相关包 Race、Vet，以及包含消融基准代码的 Staticcheck 全部通过；发布源码仅将 `main.go` 的版本字符串由 `0.0.3` 改为 `0.0.4`，其余受测 Go 源码及模块文件与消融记录一致；原始摘要保持不变。安装更新只执行了预览。
